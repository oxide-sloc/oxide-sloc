1. Overview

oxide-sloc is a cross-platform source-line-of-code (SLOC) analysis workbench built in Rust. It counts code, comment, and blank lines across 41 programming languages, detects unit tests, tracks SLOC trends over time, and exports results in JSON, HTML, PDF, CSV, and Excel formats.

Architecture

oxide-sloc is a 7-crate Rust workspace with a shared analysis core and multiple delivery surfaces:

CrateRole
sloc-cliClap CLI, binary entry point (oxide-sloc)
sloc-configAppConfig schema, TOML parsing, enums
sloc-coreFile discovery, decoding, aggregation, JSON model
sloc-gitGit CLI wrappers, webhook parsing, schedule store
sloc-languagesLanguage detection and lexical line analyzers
sloc-reportHTML rendering (Askama) and PDF export (headless Chrome)
sloc-webAxum HTTP server, form handlers, artifact storage

Data Flow

CLI / Web form
  → AppConfig (TOML + CLI flag overrides)
  → sloc_core::analyze()
      → file discovery (ignore-aware, glob filters)
      → byte decoding  (UTF-8 → UTF-16 → Windows-1252 fallback)
      → language detection (extension, shebang, override map)
      → sloc_languages::analyze_text()  [lexical state machine]
      → AnalysisRun { per_file_records, totals_by_language, warnings }
  → render_html() / write_pdf_from_html()
  → JSON, HTML, PDF, CSV, or XLSX artifact

2. Installation

2a. Quick Start (run.sh)

The simplest path on any machine with Git Bash (Windows) or Bash (Linux/macOS). This script automatically installs oxide-sloc on first run, then opens the web UI. 

bash scripts/run.sh

On subsequent runs it skips the install step and goes straight to serving on http://127.0.0.1:4317.

2b. Air-Gapped / Offline Install

oxide-sloc is designed for environments with no internet access and no pre-installed Rust. Every dependency is committed to the repository:

AssetFilePurpose
Rust crate sourcesvendor.tar.gz.aa + .ab + .ac (~115 MB)~328 crates for cargo build --offline
Rust toolchaintoolchain/rust-toolchain-*.tar.gz.aa, .abrustc + cargo, split ≤45 MB/part
Toolchain checksumstoolchain/checksums.sha256Verified before extraction
# On any machine — clone the repo (USB / network share), then run:
bash scripts/install.sh

install.sh decision tree:

  1. Binary already present → exit (nothing to do)
  2. dist/ pre-built archive → extract
  3. --online flag + no cargo → download from GitHub Releases (opt-in, Linux)
  4. Bundled toolchain present + no cargo → extract into .tools/, bootstrap Rust
  5. cargo on PATH → decompress vendor, write .cargo/config.toml, build from source
  6. Nothing available → print instructions and exit 1

2c. Docker

docker compose up -d      # build and start
docker compose logs -f    # tail logs
docker compose down       # stop

The container binds to 0.0.0.0:4317, suppresses browser auto-open, and disables file-picker routes. Set SLOC_BROWSER_NOSANDBOX=1 for PDF generation inside Docker.

2d. systemd (Linux Bare-Metal / VPS)

# Install binary
sudo install -m 755 target/release/oxide-sloc /usr/local/bin/oxide-sloc

# Create dedicated user
sudo useradd --system --no-create-home --shell /usr/sbin/nologin oxide-sloc
sudo mkdir -p /opt/oxide-sloc/out
sudo chown -R oxide-sloc:oxide-sloc /opt/oxide-sloc

# Install and enable service
sudo cp deploy/oxide-sloc.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now oxide-sloc

The binary is oxide-sloc. Running with no subcommand starts the web UI (same as serve).

3b. report

Re-render a report from a saved JSON result without re-scanning.

oxide-sloc report <RESULT_JSON> [--html-out PATH] [--pdf-out PATH] [--csv-out PATH] [--xlsx-out PATH] [--open]
oxide-sloc report out/result.json --html-out out/report.html --open
oxide-sloc report out/result.json --pdf-out out/report.pdf

3c. diff

oxide-sloc diff <BASELINE_JSON> <CURRENT_JSON> [OPTIONS]
FlagDescription
--json-out, -jWrite delta JSON
--csv-out, -cWrite delta CSV
--xlsx-out, -xWrite delta Excel workbook

3d. serve

Start the localhost web UI on port 4317 (default when no subcommand given).

oxide-sloc serve [--config PATH] [--bind ADDR] [--server]
FlagDescription
--bind <ADDR>Override bind address (e.g. 0.0.0.0:8080). Higher priority than SLOC_BIND.

3e. init

Generate a fully commented starter .oxide-sloc.toml config file.

oxide-sloc init [PATH] [--force]

Default output path: .oxide-sloc.toml in the current directory. Use --force to overwrite.

3f. validate

Validate a .oxide-sloc.toml config file without running a scan. Checks path existence, glob syntax, and field constraints.

oxide-sloc validate [--config PATH]

3h. git-scan

Clone (or fetch) a repository and scan it at a specific branch, tag, or commit SHA.

oxide-sloc git-scan <REPO> [--git-ref <REF>] [--json-out PATH] [--html-out PATH] [--csv-out PATH]
oxide-sloc git-scan https://github.com/myorg/myrepo --git-ref main --json-out scan.json

3i. git-compare

Scan two git refs and produce a delta comparison report.

oxide-sloc git-compare <REPO> <BASELINE_REF> <CURRENT_REF> [OPTIONS]
oxide-sloc git-compare /path/to/repo v1.0.0 v1.1.0 --csv-out delta.csv

3j. watch

Poll a repository branch on a configurable interval and scan on every new commit.

oxide-sloc watch <REPO> [--branch BRANCH] [--interval SECS] [--output-dir DIR]

Minimum poll interval: 60 seconds. Default: 300 seconds. Scans are written to OUTPUT_DIR/<sha8>.json when --output-dir is set.

3k. pr-comment

Post an SLOC diff comment to a GitHub or GitLab pull/merge request. Designed for Jenkins / CI post-build steps.

oxide-sloc pr-comment <CURRENT_JSON> \
  --provider github \
  --repo owner/repo \
  --pr-number 42 \
  --token $SLOC_VCS_TOKEN \
  [--baseline BASELINE_JSON] \
  [--report-url https://...]
Flag / EnvDescription
--providergithub (default) or gitlab
--api-url / SLOC_VCS_API_URLOverride API base URL (self-hosted instances)
--repo / SLOC_VCS_REPOowner/repo or GitLab project path
--pr-number / SLOC_PR_NUMBERPR / MR number
--token / SLOC_VCS_TOKENAPI token (repo scope for GitHub, api for GitLab)
--baselineBaseline JSON (optional) — shows delta section if provided

5. REST API Reference

All endpoints are served from the same Axum process. Authentication is via Authorization: Bearer <key> or X-API-Key: <key> header when SLOC_API_KEY is set.

Analysis & Scan

POST/analyzeSubmit a scan job (form data). Returns run ID; results are fetched asynchronously via /api/runs/{id}/status.
GET/api/runs/{wait_id}/statusPoll async run status: pending, running, complete, error.
POST/api/runs/{wait_id}/cancelCancel a running analysis.
GET/runs/result/{run_id}Retrieve the final HTML result page for a completed run.
GET/api/runs/{run_id}/pdf-statusPoll PDF generation progress.
GET/runs/{artifact}/{run_id}Download a specific artifact (json, html, pdf, csv, xlsx) for a run.

Metrics API

GET/api/metrics/latestJSON summary of the most recent completed scan.
GET/api/metrics/{run_id}JSON summary for a specific run ID.
GET/api/metrics/historyJSON array of all completed scan summaries (newest first).
POST/api/ingestIngest a pre-computed JSON analysis result (for CI-driven scans).
GET/api/project-historyHistorical scan registry for a specific project path.

Coverage

GET/api/suggest-coverageSuggest LCOV files auto-detected from the most recent scan's paths.

Scan Profiles

GET/api/scan-profilesList saved scan profiles.

Utilities

8. Security

Authentication

Set SLOC_API_KEY to require a bearer token on every request. When set, clients must supply one of:

  • Authorization: Bearer <key> header
  • X-API-Key: <key> header
  • Session cookie set by the /auth/login form
Warning: Running in --server mode without SLOC_API_KEY logs a startup warning. In local mode the warning is suppressed.

TLS

oxide-sloc can terminate TLS directly using PEM-encoded certificate and key files:

SLOC_TLS_CERT=/etc/oxide-sloc/server.crt \
SLOC_TLS_KEY=/etc/oxide-sloc/server.key \
oxide-sloc serve --server
Recommended for production: Use a reverse proxy (Nginx, Caddy) with bind_address = "127.0.0.1:4317". TLS termination at the proxy layer avoids certificate management in the binary.

Rate Limiting

A sliding-window rate limiter enforces 60 requests per 60-second window per client IP across all routes. Requests over the limit receive HTTP 429 Too Many Requests. Failed authentication attempts trigger an IP lockout.

Path Restrictions

Set SLOC_ALLOWED_ROOTS to a colon-separated list to restrict which paths the web UI may scan. Any scan request targeting a path outside this list is rejected with 403 Forbidden.

SLOC_ALLOWED_ROOTS=/repos:/projects oxide-sloc serve --server

CORS

CORS is configured via tower-http. In local mode, origins are restricted to localhost. In server mode, configure CORS headers through your reverse proxy.

Webhook Security

Outbound webhook URLs are validated before any request is sent:

  • Must use HTTPS
  • Cloud metadata endpoints (169.254.169.254, metadata.google.internal) are blocked
  • RFC-1918 private IPs, loopback, link-local, and multicast addresses are blocked

Incoming GitHub/GitLab webhooks validate the HMAC-SHA256 signature before processing.

Security Headers

All responses include: X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, Referrer-Policy: strict-origin-when-cross-origin, and a Content-Security-Policy nonce.

Nginx Reverse Proxy Example

server {
    listen 443 ssl;
    server_name sloc.example.com;
    ssl_certificate     /etc/ssl/certs/server.crt;
    ssl_certificate_key /etc/ssl/private/server.key;

    location / {
        proxy_pass http://127.0.0.1:4317;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

11. Integrations

CI / CD

oxide-sloc ships with pre-built CI integration files:

  • .github/workflows/ci.yml — GitHub Actions CI/CD pipeline
  • Jenkinsfile — Jenkins declarative pipeline
  • ci/sloc-ci-*.toml — named CI preset configs
  • docs/ci-integrations.md — Jenkins manual setup guide

GitHub / GitLab

Use pr-comment to post SLOC diff summaries automatically on every pull request. Set up a Jenkins post-build step or a GitHub Actions job step:

# GitHub Actions example
- run: |
    oxide-sloc pr-comment current.json \
      --baseline baseline.json \
      --provider github \
      --repo ${{ github.repository }} \
      --pr-number ${{ github.event.pull_request.number }} \
      --token ${{ secrets.GITHUB_TOKEN }}

Git Webhooks

Configure your GitHub or GitLab repository to send push events to the running oxide-sloc server:

  • GitHub: POST /webhooks/github with a secret configured in SLOC_WEBHOOK_SECRET
  • GitLab: POST /webhooks/gitlab

Each push event triggers a fresh scan of the configured root paths and stores the result in the scan registry.

  --report-url https://sloc.internal/runs/result/abc123

12. Exit Codes

CodeTrigger
0Success
1Error (I/O, config, argument, or network failure)
